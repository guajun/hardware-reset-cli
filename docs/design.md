# Hardware reset CLI 总体方案

状态：草案，2026-11-17。本文与其他设计文件描述待实现行为；现有代码只提供 CubeMX 固件骨架。

## 目标与首版范围

提供一个 Windows、Linux、macOS 可调用的 Go CLI，经 USB 控制 Blue Pill 的 GPIO，替代人工按下目标板复位键。首版实现设备发现、能力查询、状态查询、定时复位、持续拉低、释放；设备仅控制自身 GPIO，不负责判断目标系统是否成功启动。

采用 USB CDC ACM + 有界 ASCII 行协议；CLI 默认文本输出，`--json` 为稳定的脚本接口。协议采用固定位置字段，避免在 STM32F103C8T6 上引入 JSON 解析器。暂不实现固件升级、自身重启、推挽高电平、任意 GPIO 寄存器访问、批量操作和持久化配置。

## 现有工程与差距

| 项目 | 当前内容 | 首版需要补齐 |
| --- | --- | --- |
| MCU | STM32F103C8T6，Cortex-M3 | 按实际芯片容量控制 RAM/Flash 占用 |
| USB | CubeMX CDC FS，48 MHz USB 时钟 | Line Coding、接收队列、发送队列、断线处理 |
| GPIO | PA0–PA7，推挽，初始低电平 | 开漏、初始释放、白名单、非阻塞定时 |
| 接收回调 | 重新挂接 USB OUT，未处理数据 | 有界缓冲、按行解析、命令调度 |
| 主循环 | 空循环 | 调度解析、GPIO 定时和响应发送 |
| CLI | 空目录 | Go 工程、设备枚举、协议、输出和打包 |

## GPIO 行为

- 首版白名单为 PA0–PA7；USB PA11/PA12、SWD、晶振及其他引脚不得通过协议修改。
- 引脚配置为开漏，写 1 释放，写 0 拉低；`RELEASED` 不代表实测高电平。
- 初始化先写释放值，再切换输出模式，避免软件初始化造成低脉冲。复位期间由目标板外部上拉保证默认电平，需用示波器验证上电与重枚举无误触发。
- `RESET` 默认 100 ms，允许 1–10000 ms，由设备计时，结束后释放；CLI 进程提前退出不影响设备结束脉冲。范围是产品限制，实际目标的最小复位时间由使用者选择。
- `ASSERT` 默认 1000 ms，`--hold-ms` 允许 1–10000 ms，到期自动释放。首版不提供无限保持，断线或主机崩溃时仍有最大保持时间。
- 同一时刻只允许一个执行中的写操作；忙时允许 `INFO`、`STATUS` 和 `RELEASE`。`RELEASE` 可取消当前操作，原操作返回 `CANCELLED`。
- USB 断开、总线复位及设备可检测到的会话关闭时立即释放全部控制引脚。不能仅依赖关闭串口触发回调；定时释放始终有效。USB suspend 不延长期限。
- 修改 `.ioc` 和生成代码需一起提交，避免下一次 CubeMX 生成恢复为推挽低电平。

## 实施顺序与验收

1. 固件安全初始化：开漏、白名单、释放和定时状态机；示波器观察上电、断线、重连与 100 ms 脉冲，无多余拉低。
2. USB 传输和协议：处理分包、粘包、超长行、非法参数、TX busy、队列满和请求重复；确认非法输入不改变 GPIO。
3. Go CLI：先实现 `list` / `info` / `status`，再实现写操作；用模拟串口覆盖协议匹配、超时、断线与多设备选择。
4. 三平台联调：设备发现、权限/占用错误、JSON 结构、退出码、取消和重连；检查编译产物与第三方依赖许可。

首版完成的判据是：可由脚本选择指定设备、执行一次复位、获得唯一对应的完成结果；超时明确返回状态未知，且不会自动重复复位。`RESET` 成功仅表示 GPIO 时序完成，不保证目标设备已经启动或业务恢复。
